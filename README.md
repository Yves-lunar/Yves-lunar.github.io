# 日常：GitHub Pages + Supabase 免费共享记事本

保留原有界面。待办、项目和日记保存到同一张 PostgreSQL 表，所有访客无需注册或手动登录即可共享读写。打开或刷新页面读取最新内容，无需部署自己的服务器。

## 新版界面

- 待办使用固定 19×19 像素的方框，三个模块在桌面上顶部对齐。
- 项目默认只显示标题和展开箭头，保存成功后自动收起；先显示前 3 个项目，底部渐隐提示可展开或收起其余项目。手动折叠时保留未保存的编辑内容。
- 上方浅铅灰色「流水账」支持随输入自动增高和全屏沉浸式书写；退出全屏保留草稿，提交后只存入「日志箱」。
- 日历默认折叠为日期按钮，点击小箭头展开，选定日期后收起。
- 第三栏仅预览最近提交的 4 条小纸条；所有小纸条（包括原有日记）均保留在底部「小纸条」中。
- 「日志箱」与「小纸条」按记录日期倒序分组，顶部快捷栏最多显示最近 10 个有记录的日期，窄屏自动减少；点击日历图标可在紧凑月历中选择其他日期，有记录的日期加深显示。选中较早日期时，快捷栏会同步显示附近日期；空白日期会提示无记录。同日记录按提交时间倒序排列。
- 归档页与全屏书写页的标题栏随正文一起滚动。
- 两个归档页和全屏书写均可用关闭按钮或 Esc 返回，保存失败时不清空草稿。

已有 Supabase 表无需修改或重新执行 SQL。存储模块将流水账作为带保留标题 `__little_days_daily_log_v1__` 的 diary 行保存，读回时映射为 log；普通日记保持原样。不要手动改动该保留标题。

## 打卡抽签

- **主页顶部「今日打卡」**：一打开网页就能打卡。顶行是本周 7 天的打卡情况（做了的日子标绿，下面写着当天抽到的金额），以及连续天数和待充金额。还没打卡时直接显示表单：做了/没做、一句「她今天……」、0–10 分。标了「做了」并保存后，旁边出现签筒，可以直接抽。抽完后整条收成一行（已打卡 · 抽到 X 元 · 修改），不占地方。
- **导航栏「打卡」页**：完整版的今天、抽签、抽到的钱（累计抽到 / 已充 / 待充、「本周已充」、充值记录）、统计（打卡天数、当前连续、各档抽中次数横条图）和月历（点某一天看当天内容和金额）。
- **规则**：每天一条打卡，当天可以随时补写、修改；过去的日子只读，不能补抽。只有当天保存为「做了」才能抽签，一天一次，抽完不能重抽，「做了」也不能再改成「没做」（一句话和评分仍可改）。抽签前会先从云端重新读取，如果另一台设备已经抽过，直接显示那支签，不会再抽。保存失败重试时用的是同一支签，不会借机重抽。
- **换日时间**：`config.js` 里的 `dayStartsAt: 4` 表示凌晨 4 点前打卡、抽签都算前一天（像游戏每日 4 点重置），这段时间页面上会提示「4 点前仍算这一天」。改成 0 就是零点换日。只影响打卡抽签，流水账、小纸条仍按实际日期。
- **额度和概率**在 `config.js` 的 `LITTLE_DAYS_CHECKIN` 里，改完刷新页面即可；已抽到的记录不受影响。概率按权重计算，加起来不是 100 也能用。幸运暴击与额度分开独立判定。按默认设置，每支签平均约 36.12 元。
- **存储**：和流水账、小工具一样，存进同一张 `little_days_items` 表的 diary 行，用保留标题区分：打卡 `__little_days_checkin_v1__`、抽签 `__little_days_draw_v1__`、充值 `__little_days_topup_v1__`；`day` 是日期，`body` 是 JSON。不改表结构、不需要执行 SQL，原有记录一条都不动。不要手动改这几个保留标题。抽签记录界面上不提供删除；充值记录可以删除，10 秒内可撤回。
- **十月补录**：2026-10-05 至 10-31 共 27 天的打卡（22 天做了、5 天没做）已直接写入云端，`body` 里带 `"imported"` 标记，没有补抽签。评分支持 0.5 分（如 6.5）。
- **部署后**：每台设备先刷新一次再用打卡。还在跑旧缓存页面的设备，会把这几类新记录显示成内容是 JSON 的小纸条；请不要在旧页面里删除它们。

## 流水账标签

- 写流水账时，正文下面「标签」那一排是胶囊形标签：点一下选中，再点取消；点「＋ 添加」可以写新的（最多 16 个字，每条最多 12 个），回车确认，Esc 取消。常用标签会按使用次数排在前面。
- 打开「日志箱」后，顶部可以按标签选看（再点一次或点「全部」恢复）。每条流水账「编辑」时也能增删标签，保存后立即生效。
- 标签存在这条流水账的标题后缀里，例如 `__little_days_daily_log_v1__:["求职","散步"]`；没有标签的流水账标题保持原样，不需要改表。

## 备份与隐私

- 页面底部有「导出备份」：点一下把表里全部记录（包括流水账、小纸条、打卡、抽签、充值）原样下载成 `little-days-backup-日期.json`。建议偶尔点一次存起来；需要恢复时可以照这个文件重新写回。

## 第一步：创建数据表（只需一次）

1. 打开 [项目 SQL Editor](https://supabase.com/dashboard/project/wgabwfewcexgcicdqmjd/sql/new)。
2. 复制仓库中 **supabase-init.sql** 的全部内容，粘贴到新查询并点击 **Run**。
3. 显示成功后，进入 Table Editor，确认存在 `little_days_items` 表。

脚本创建表、开启 RLS，并仅给该表设置共享读写权限。访客都可以读取、修改和删除别人的记录，这是当前共享记事本的预期行为。它不删除数据，也不改变其他表的访问策略。无需手动创建字段。

如提示权限或数据表无法访问，在 Integrations → Data API 确认 Data API 已启用且 `public` schema 可访问。脚本已包含该表需要的 GRANT 和 RLS 策略，无需全局开启新表默认公开权限。

**不需要执行腾讯云的建表文件，也不需要购买跨域域名功能或配置登录回调地址。**

## 第三步：验证共享读写

导航栏的「小工具」是独立文本页，不在总览主页显示。上方输入框支持自动增高与全屏书写，提交后按新到旧显示在下方列表中；条目支持编辑、删除和 10 秒撤回。数据使用现有表的独立类型标记保存，不混入流水账和小纸条，无需执行新 SQL。更新时一并上传 `supabase-store.js`、`notebook-ui.js` 和 `notebook.css`。

1. 在电脑上添加待办、项目和日记。
2. 用手机或无痕窗口打开网站，确认能读取这些内容且无需登录。
3. 在第二台设备修改项目、勾选待办，刷新第一台设备查看更新。
4. 删除一条测试记录，刷新另一台设备确认删除同步。

5. 打卡抽签：在电脑上打卡并抽签，然后在手机上打开（或刷新），确认「今日打卡」显示的是同一支签、同样的金额，并且没有出现「抽一支签」按钮。再在手机上点「本周已充」记一笔，回电脑刷新，确认待充和充值记录一致。页脚显示「内容已同步」表示最近一次读取成功。

每次操作只修改对应记录，不覆盖整个记事本。列表会分页读取。保持原有的「打开或刷新读取最新数据」方式，不提供逐字实时协同；同时编辑同一条记录时，后保存的字段覆盖先保存的字段。

日志箱中的每条流水账支持「编辑 → 保存修改」和「取消」。编辑只更新正文，保留原来的日期和记录，不会产生副本；保存失败时编辑文字会保留，可重试。

项目、流水账和小纸条删除后会显示「撤回」，10 秒内可恢复原记录；连续删除时各自保留撤回按钮。10 秒后才向云端提交删除，失败会恢复记录并提示错误。倒计时内刷新或关闭页面会取消尚未提交的删除。待办保持原来的删除方式。

更新上传网页文件不会清空已保存的 Supabase 数据。继续使用当前 `config.js` 中的项目和数据表即可继承现有日志、待办、项目和小纸条；本次更新无需重新执行 SQL 或新建数据表。

项目按最近保存时间排列，新建项目也会参与排序。点击默认项目标题会自动选中文字，可直接输入新名称。正文直接显示加粗、下划线、删除线、列表和颜色效果，无需切换预览；输入 `[]` 或 `[ ]` 自动变成可勾选方框，`**文字**`、`~~文字~~` 和行首列表符号也会自动转换。工具栏和 Ctrl+Z 支持撤销，Ctrl+Shift+Z / Ctrl+Y 支持重做。输入与格式修改最后仍需点击「保存修改」。

一次只展开一个项目；点击另一个项目会收起前一个，点击页面空白处会收起所有项目。折叠有短动画，并保留当前页面中未保存的草稿及撤销记录。系统开启减少动态效果时取消动画。

项目编辑时间以兼容标记保存在正文开头，由存储层自动隐藏；原有纯文本和上一版 Markdown 项目直接兼容，创建时间保持不变。富文本正文使用带版本标记的受限 HTML，读取时过滤脚本、事件属性及无关标签。此次更新请上传 `index.html`、`project-editor.js`、`notebook-ui.js`、`notebook.css`；保留之前版本的 `supabase-store.js` 和 `notebook-model.js`，无需修改数据库。更早的项目没有历史编辑时间，第一次编辑前按创建时间排列。

旧 Sites / CloudBase 数据不会自动迁移。新表为空属于正常情况；如有需要保留的旧数据，应另外备份和迁移。

## 排错

- `PGRST205` / 表未创建：确认在此 Supabase 项目执行了 `supabase-init.sql`；刚创建后等待元数据刷新。
- 401：确认 URL 和 Publishable Key 属于同一项目。
- 403 / 42501：检查 Data API、表级 GRANT 和 RLS 策略是否生效。
- 读取为空：新表本来就为空；如果表中有数据却读不到，检查 RLS 读权限。
- 网络失败：确认项目未暂停，并测试当前设备能否访问项目接口。
